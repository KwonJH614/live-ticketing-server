# k6 부하 테스트 리포트 — 전체 티켓팅 플로우

## 테스트 개요

| 항목 | 값 |
|------|-----|
| **테스트 시나리오** | 이벤트 목록 → 대기열 → WebSocket 대기 → 좌석 조회 → 좌석 선점 |
| **최대 동시 접속자** | 2,000 VU |
| **테스트 시간** | 120초 (ramping) |
| **총 HTTP 요청** | 50,441건 |
| **총 WebSocket 세션** | 11,327건 |
| **총 플로우 실행** | 10,743회 |
| **좌석 선점 성공** | 100건 (100석 전석 매진) |
| **대기열 허용 인원** | 200명 (동시 통과) |

> 로그인은 setup 단계에서 사전 처리되어 메인 부하에서 제외됨.

## 병목 분석

| 구간 | p95 | 분석 |
|------|-----|------|
| 이벤트 목록 | 564.9ms | 2,000 VU 피크에서 가장 느린 구간. DB 페이지네이션 조회 |
| 대기열 등록 | 548.7ms | Redis ZSet rank 조회 + 추가. 경합 구간 |
| 이벤트 상세 | 497.2ms | 대기열 access 검증 + DB 조회 |
| 좌석 선점 | 508.3ms | Redis 홀드 + DB 검증 |
| 좌석 조회 | 397.7ms | 가장 빠름. 단순 SELECT |

> **병목 구간**: 이벤트 목록 / 대기열 등록이 2,000 VU 피크에서 p95 550ms 내외.
> 5xx 에러 0건 유지, 모든 구간 p95 < 600ms로 목표치 내 안정적 처리.
> 개선 방안: 이벤트 목록 Redis 캐싱, DB 인덱스 튜닝.

## 테스트 환경

| 항목 | 값 |
|------|-----|
| 서버 | Spring Boot 3.5 + WebFlux (Netty) |
| DB | PostgreSQL (로컬, R2DBC pool max-size 100) |
| 캐시/큐 | Redis (로컬) |
| 테스트 도구 | Grafana k6 |
| 테스트 환경 | 단일 로컬 PC (k6 + 서버 + DB + Redis 동일 머신) |
