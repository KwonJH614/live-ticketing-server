## 병목 분석

| 구간 | p95 | 분석 |
|------|-----|------|
| 로그인 | 534.0ms | BCrypt 해싱으로 CPU 바운드, 500 VU에서도 안정적 |
| 대기열 등록 | 81.9ms | Redis ZSet 기반, 가장 빠른 구간 |
| 좌석 조회 | 646.9ms | DB 조회 구간, 500 VU에서 가장 느린 병목 |
| 좌석 선점 | 376.5ms | Redis 기반 홀드, DB 확인 포함 |

> **병목 구간**: 좌석 조회(PostgreSQL)가 500 VU 피크에서 p95 646.9ms로 가장 느림.
> 개선 방안: DB 커넥션 풀 튜닝, 좌석 목록 Redis 캐싱, 인덱스 최적화.
